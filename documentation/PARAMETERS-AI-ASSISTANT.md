# AI 助手参数手册

本文逐项说明 AI 助手的可调参数与内部阈值：默认值、合法范围、影响什么、在哪里改。原理与链路见 [ARCHITECTURE-AI-ASSISTANT.md](ARCHITECTURE-AI-ASSISTANT.md)。

> 所有参数都在本机生效。模型的实际上下文长度、价格、工具支持由你配置的接口决定；本文的默认值只是应用侧的兜底与预算口径。

---

## 一、总览

| 参数 | 默认 | 范围 / 上限 | 影响 |
| --- | --- | --- | --- |
| 协议 `protocol` | `openai` | `openai` / `anthropic` | 请求路径与请求体格式 |
| 流式 `stream` | 开 | 开 / 关 | 逐字输出或一次性返回 |
| 上下文 `contextTokens` | 8192 | 1024 – 10,000,000 | 历史注入与裁剪的总预算 |
| 主回答温度 | 0.3 | 代码内固定 | 回答随机性 |
| 主回答 `max_tokens` | OpenAI 不发送；Anthropic 2048 | —— | 单次回答长度上限 |
| 工具规划 tokens | 500 | 代码内固定 | 规划阶段单次调用上限 |
| 工具轮数 / 次数 | 3 轮 / 6 次 | 代码内固定 | 单轮最多查多少 |
| 单工具超时 | 8 s | 可传参覆盖 | 防止工具卡住 |
| 工具结果注入 | 8000 字符 | 代码内固定 | 回填给模型的上下文上限 |
| 自动记忆 | 开 | 开 / 关 | 回答后是否自动写长期记忆 |
| AI 写操作 | 每次确认 | 每次确认 / 关闭 | 是否允许修改目标、基线、导出 |
| 记忆注入块 | 1200 字符 | 代码内固定 | 每轮最多注入多少记忆文本 |
| 记忆检索条数 | 8 | 代码内固定 | 按需检索最多返回几条 |
| 摘要正文 | 1600 字符 | 代码内固定 | 滚动摘要上限 |
| 对话数量 | 30 条 | 代码内固定 | 超出按更新时间淘汰 |
| 用量日志 | 200 条 | 代码内固定 | 透明面板保留的调用明细 |
| 请求日志 | 10 条 | 代码内固定 | 实际请求体保留条数 |

## 二、模型档案

设置 → 大模型 → 档案。每个档案是一套独立的接口配置；活动档案由 `llmActiveProfileId` 指向。

| 字段 | 说明 | 默认 / 约束 |
| --- | --- | --- |
| 名称 | 档案显示名 | 任意 |
| 协议 | `openai` 兼容 `/chat/completions`；`anthropic` 走 `/v1/messages` | `openai` |
| Base URL | 接口根地址，如 `https://api.example.com/v1` | 必填；末尾 `/` 会自动去掉 |
| API Key | 仅存 IndexedDB `llm:profiles` | 必填；不进 localStorage、不进设置导出 |
| 模型 ID | 如 `gpt-4o-mini` / `deepseek-chat` | 必填；可从 `/models` 拉取 |
| 流式 | 端点不支持 SSE 时关闭 | 开 |
| 上下文长度 | 助手裁剪历史的依据 | 8192；最小 1024，最大 10,000,000 |

**辅助档案**（可选）：用于工具规划、记忆写作、摘要、数字修正等辅助任务；留空则跟随活动档案。把便宜的小模型设为辅助档案，可以显著降低工具轮次的成本。

**上下文长度识别顺序**：接口返回的元数据（`context_length` / `max_model_len` / `top_provider.context_length` 等）→ 内置已知模型目录 → 保持当前值。模型更新后内置目录可能过期，以接口返回或手动填写为准。

**旧配置迁移**：旧版三字段 `llmBaseUrl` / `llmApiKey` / `llmModelId` 只在启动时读取一次，生成一份档案后不再消费；此后一切以档案为准。

## 三、请求参数

| 调用 | 温度 | max tokens | 说明 |
| --- | --- | --- | --- |
| 主回答（流式） | 0.3 | OpenAI 不发送；Anthropic 2048 | 用户看到的最终回答 |
| 工具规划 | 0 | 500 | 决定本轮调用哪些工具 |
| 记忆检索路由器 | 0 | 200 | 只决定是否查记忆、给检索词 |
| 记忆写作（自动） | 0.2 | 300 | 从一轮对话提炼 0–3 条记忆 |
| 记忆写作（选择卡） | 0.2 | 300 | 从选择结果提炼 1 条 |
| 手动「记住」 | 0.2 | 240 | 从一条回复提炼候选 |
| 数字修正 | 0 | 同主回答 | 只改无依据的数字 |
| 滚动摘要 | 0.1 | 同主回答 | 后台生成正式摘要，输出截到 1600 字符 |

> **注意**：OpenAI 兼容路径的主回答没有设置 `max_tokens`，回复长度只受模型自身与上下文预算限制；Anthropic 路径固定 2048。如果你希望严格限制长度，需要在 `llmClient.ts` 的 `buildChatBody` 里补 `max_tokens`。

## 四、上下文预算

一次生成的总预算是 `contextTokens`（默认 8192）。应用按以下顺序分配：

| 项目 | 预算 | 说明 |
| --- | --- | --- |
| 回复预留 | `ceil(context × 25%)` | 给模型输出留空间 |
| 历史对话 | 最多 `context × 60%`，且不超过 `context − 对话 − 预留 − 额外 − 512` | 从最旧开始裁 |
| 系统提示 + 记忆 + 文档 + 工具结果 | 占用剩余预算 | 超出后重新裁剪历史 |
| 单轮最小生成预算 | 1024 tokens | 防止系统提示过长导致无输出 |

**历史上下文内部再分配**（`buildAssistantContext`）：

| 部分 | 预算 |
| --- | --- |
| 用户画像 / 靶标 | 固定保留 |
| `/attach` 钉选记录 | 剩余预算最多 60% |
| 按周 / 按模式聚合 | 剩余预算最多 60%；最多 8 周，预算紧时逐步减少 |
| 基线 Δ | 剩余预算最多 35% |
| 最近记录明细 | 剩余预算；最多 40 条，从最新往回装 |

**裁剪与摘要**：

- 历史超预算时从最旧消息开始裁，最多 3 轮「裁剪 → 摘要 → 重算」；
- 被裁掉的消息进入滚动摘要：先本地摘录，再后台调用摘要模型；
- 摘要正文上限 1600 字符；摘要输入每条消息最多 600 字符；摘要提示词要求最多 400 字；
- 摘要与最近消息冲突时，以最近消息为准。

## 五、工具循环

| 限制 | 值 | 位置 |
| --- | --- | --- |
| 最大轮数 | 3 | `assistantAgent.ts` |
| 最大工具调用数 | 6 | `assistantAgent.ts` |
| 单工具超时 | 8000 ms | `assistantAgent.ts`（可传参覆盖） |
| 只读工具并发 | 4 | `assistantAgent.ts` |
| 结果注入上限 | 8000 字符 | `assistantAgent.ts` |
| 规划调用 max tokens | 500 | `assistantAgent.ts` |
| 参数非法修正 | 1 次 | `assistantAgent.ts` |
| `query_records` 条数 | 默认 8，最大 20 | `assistantTools.ts` |
| `get_trends` 最近 N 条 | 默认 8，最大 20 | `assistantTools.ts` |
| `search_chats` 条数 | 默认 5，最大 8 | `chatSearch.ts` |

写操作（`propose_action`、`create_plan`、`update_plan`）不并行执行，必须等用户确认；`assistantWrites = off` 时直接拒绝写操作工具。

## 六、记忆参数

| 参数 | 默认 / 值 | 说明 |
| --- | --- | --- |
| 自动记忆开关 | 开 | 设置 → 大模型 → 记忆 / 记忆页 |
| 每轮自动保存上限 | 3 条（选择卡回答 1 条） | 防止一次写入过多 |
| 单条文本请求上限 | 80 字（工具描述） | 模型被要求写短句 |
| 单条文本存储上限 | 300 字 | `MEMORY_TEXT_MAX`，超长截断 |
| 置顶记忆 | 每轮注入 | 不参与相关度筛选 |
| 注入块上限 | 1200 字符 | 超出按相关度 / 新鲜度截断 |
| 按需检索条数 | 8 | `searchMemories(query, 8)` |
| 检索评分 | 命中 × 3 + 重要度 × 0.6 + 新鲜度 | 14 天内 1.2 / 60 天内 0.6 / 更早 0.2 |
| 相似更新阈值 | Jaccard ≥ 0.8 | 相似条目更新而非新增 |
| 整理合并阈值 | Jaccard ≥ 0.65 | 每次最多 3 组；旧条目标记 superseded |
| 自动保存门控 | 寒暄 / 纯提问 / <6 字 / 与本人或训练无关 → 跳过 | `shouldAutoSaveMemory` |
| 自动保存文本长度 | ≤ 160 字 | 超过不进入自动记忆 |
| 未成年过滤 | 激素 / 手术 / 出柜等词 | 自动记忆写入前过滤 |

**作用域**：`global` / `chat` / `plan`；**状态**：`active` / `superseded` / `expired`；`validUntil` 到期后不再召回。私密对话强制 `memoryOff`，不读也不写记忆。

## 八、隐私与写权限

| 设置 | 默认 | 取值 | 行为 |
| --- | --- | --- | --- |
| 自动记忆 `memoryAutoSave` | `auto` | `auto` / `off` | 关闭后仍可手动「记住」 |
| AI 写操作 `assistantWrites` | `confirm` | `confirm` / `off` | `off` 时禁止改目标 / 基线 / 导出 |
| 对话私密 | 关 | 开 / 关 | 切换时记录 `privateSince` 并强制 `memoryOff` |
| 本对话记忆 | 开 | 开 / 关 | 只影响写入；读取仍然正常 |

**私密的边界**：私密是模式而非永久脱敏。退出私密后 `privateSince` 清空，之前私密期间的消息会重新进入后续上下文；自动记忆仍保持关闭，需手动再开。

## 九、用量、费用与日志

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 用量日志 | 200 条 | 每次实际调用一条；缓存命中不计 |
| 请求日志 | 10 条 | 展示实际发出的请求体 |
| 单条消息截断 | 4000 字符 | 请求日志体积控制 |
| token 估算 | CJK ≈ 1 token/字；其他 ≈ 4 字符/token | 服务商未返回 usage 时兜底，带 `est` 标记 |
| 价格 | USD / 百万 tokens | 优先用接口返回；否则内置目录；可手动填 |
| 费用估算 | 输入 tokens × 输入单价 + 输出 tokens × 输出单价 | 仅参考 |

请求日志只记录请求体，不记录 API Key（Key 在 Authorization 头）。用量与日志都在本机 IndexedDB，不进设置导出。

## 十、推荐配置

| 场景 | 建议 |
| --- | --- |
| 只问参数 / 用法 | 8k 上下文的便宜模型即可；把辅助档案设为同款或更小模型 |
| 经常问趋势 / 多轮训练计划 | ≥32k 上下文；辅助档案用低温度小模型；开启流式 |
| 长对话、长期追踪 | ≥128k 上下文或定期开新对话；依赖滚动摘要时保持摘要模型可用 |
| 成本敏感 | 主档案用较强模型回答，辅助档案用便宜模型做规划 / 记忆 / 摘要 |
| 工具调用不稳定 | 优先选支持 function calling 的模型；关闭流式重试；检查档案协议 |

## 十一、调参建议

1. **上下文不是越大越好**：上下文越大，单次请求越贵；长对话靠摘要和工具查询，而不是把所有历史塞进去。
2. **辅助档案是最划算的开关**：规划、记忆、摘要、数字修正都是短请求，用便宜模型即可；主回答保留质量。
3. **工具调用失败先看协议**：部分 OpenAI 兼容端点不支持 `tools`，助手会自动回退到预注入上下文；此时趋势 / 记录查询能力会下降。
4. **私密对话不写记忆**：如果发现「它怎么又记得」，先检查对话是否退出过私密、以及全局自动记忆是否仍开着。
5. **数字可信度**：助手只在调用过工具时校验数字；纯常识回答不做数字审查，重要结论仍应回看记录。
6. **费用异常**：检查请求日志里的 `messages` 长度与模型单价；长系统提示 + 大上下文 + 多轮工具会叠加。

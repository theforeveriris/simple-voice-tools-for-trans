# 音高检测 · YIN 算法

> 源码：`src/lib/audio/pitch.ts`（YIN 实现）+ `src/lib/audio/pitchCore.ts`（共享基础件）
> ｜ 实时运行于每一帧（约 60fps），单帧约 1.5M 次乘加运算

## 为什么选择 YIN

项目早期的音高检测基于**频谱谐波匹配**：把每个候选音符的谐波位置在 FFT 频谱上打分，
取得分最高者。它有两个致命问题：

1. **半音量化**：候选频率直接取自十二平均律音高表，输出频率永远吸附在音符网格上
   （例如 196.00Hz 而不是真实的 193.8Hz），画出来的音高曲线是台阶状的；
2. **基频缺失敏感**：电话语音、低音歌手的基频能量弱，谐波打分容易错到倍频上。

YIN（Alain de Cheveigné & Hideki Kawahara, 2002；完整出处见 [REFERENCES.md](REFERENCES.md)）是时域算法，直接在波形上找重复周期，
输出**连续、亚赫兹级精度**的基频，并且自带周期性置信度——非常适合绘制平滑曲线。

## 算法原理

YIN 的输入是一帧时域信号 `x`。分析窗长 W 取输入的一半：**实时路径**传入 AnalyserNode
的完整 4096 样本缓冲，W = 2048；**离线/导入管线**（32 kHz 统一口径）帧长 2048，
W = 1024。

### 第 1 步：差分函数 d(τ)

$$d(\tau) = \sum_{i=0}^{W-1} (x[i] - x[i+\tau])^2$$

直觉：如果信号以 τ 为周期，那么 `x[i] ≈ x[i+τ]`，差分在 τ 的整数倍处接近 0。
τ 的搜索范围由频率上下限决定（`pitchMinHz` / `pitchMaxHz`，实验性可调，默认 60–600 Hz），
并受 W 钳制：

- τ_min = fs / maxHz、τ_max = fs / minHz——以 44.1 kHz 为例约 **74**（600Hz）到 **735**（60Hz）；
  常见 48 kHz 设备为 80–800；32 kHz 离线管线为 53–533。

### 第 2 步：累积均值归一化（CMND）

$$d'(\tau) = \frac{d(\tau) \cdot \tau}{\sum_{j=1}^{\tau} d(j)}$$

裸的差分函数有一个经典陷阱：在真实周期 τ₀ 的 **2τ₀、3τ₀** 等处，d(τ) 同样很小，
甚至经常比 τ₀ 处更低——直接取全局极小会得到**八度向下**的错误。

CMND 把每个点的差分除以"它之前所有差分的累积平均"：在首个真实周期处 d' 会降到
远低于 1，而在次周期处由于累积平均已经被之前的低谷拉低，d' 不会显著低于 1。
这一步是 YIN 抗八度错误的核心。

> 实现说明：`pitchCore.ts` 的归一化从搜索下限 τ_min 开始累积（分母系数 `τ - τMin + 1`，
> `cmnd[τMin] = 1`），与上式在 τ ≫ τ_min 时等价；这是为跳过不搜索的短周期区间。

### 第 3 步：绝对阈值搜索

从 τ_min 向后扫描 d'。扫描时同时保留全局最小 CMND：
- 遇到第一个低于阈值 `yinThreshold`（默认 0.14，实验性可调 0.05–0.38）的点后，
  继续走到该谷底的局部极小，作为候选；
- 若整段没有任何点低于阈值，但全局最小值仍 ≤ 阈值 + 0.31（默认口径 0.45），
  仍采用该候选（低置信度，`prob` 会偏低）；
- 只有全局最小值 > 阈值 + 0.31（波形没有明显周期性），或插值后的频率落在
  `minHz`–`maxHz` 之外，才返回 null；
- 置信度输出 `prob = 1 - bestVal`。

"第一个低于阈值的谷"而非"全局最低谷"是刻意的：语音是非平稳信号，取更深的次周期谷
反而更容易跳到倍频。

### 第 4 步：抛物线插值

τ 只能取整数样本，分辨率受限于 fs/τ（在 200Hz 附近约 2~3Hz 一跳）。对极小点及其两个
邻点做抛物线拟合，取抛物线顶点作为更精确的 τ：

$$\tau^* = \tau + \frac{d'(\tau-1) - d'(\tau+1)}{2\,(d'(\tau-1) - 2d'(\tau) + d'(\tau+1))}$$

最终 `freq = sampleRate / τ*`，精度达到亚赫兹级。

## 参数一览

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 分析缓冲 | 4096 样本（实时） | AnalyserNode fftSize，时域数据；离线/导入管线帧长 2048 @ 32 kHz |
| YIN 窗长 W | 实时 2048 / 离线 1024 | 输入长度的一半 |
| 频率范围 | 60 – 600 Hz（默认） | `pitchMinHz` / `pitchMaxHz` 实验性可调（40–200 / 300–1200，上限 ≥ 下限+100） |
| CMND 阈值 | 0.14（默认） | `yinThreshold` 实验性可调 0.05–0.38；越小越严格，误检越少但哑音增多 |
| 放弃阈值 | 阈值 + 0.31（默认 0.45） | 最小 CMND 超过则判为无声帧，随阈值联动 |
| 无声门限 | 帧电平 > `voicedGateDb`（默认 -55 dB） | 能量太低直接跳过检测，实验性可调（见能量分析文档） |

## 源码导读

公共基础件在 `src/lib/audio/pitchCore.ts`（YIN / pYIN / MPM 三处同款逻辑收敛到一处）：

- `tauRange(samples, sampleRate, minHz, maxHz)` —— 推算 τ 搜索区间（`samples` 用于
  检查帧长是否足够）；
- `computeCmnd(...)` —— 差分函数 + 累积均值归一化（CMND）；
- `parabolicRefine(...)` —— 抛物线插值细化（三处同款公式，修插值 bug 只改这里）；
- `ensurePitchScratch(len)` —— 模块级按需增长复用缓冲（`diffBuf` / `cmndBuf` /
  `nsdfBuf` / 极值候选池），实时循环 60fps 稳态零分配；
  同线程内调用严格串行（实时循环 / 离线管线 / Worker 各自独占本线程），复用安全。

`src/lib/audio/pitch.ts`：

- `detectPitchYin(samples, sampleRate, minHz?, maxHz?)` —— 主函数，四个步骤与上文一一对应：
  1. 调用 `computeCmnd` 求出归一化差分序列；
  2. 扫描寻找第一个低于阈值的谷，找不到返回 `null`；
  3. `parabolicRefine` 抛物线插值（局部变量 `betterTau`），换算频率；若结果超出
     `minHz`–`maxHz` 则返回 `null`（不做夹取）；
  4. `prob = 1 - 最小 CMND 值` 作为置信度。
- `rmsDb(samples)` —— 帧能量计算，被录音引擎同时用于能量曲线与有声门限。

## 复杂度与实时性

- 时间复杂度 O(W · τ_max)：实时 W=2048、48 kHz 下 τ_max=800，约 **1.6M 次乘加/帧**
  （44.1 kHz 约 1.5M；32 kHz 离线管线 W=1024、τ_max=533，约 0.55M）；
- 60fps 下实时路径约 90M 次运算/秒，现代桌面浏览器单帧耗时 < 2ms；
- pYIN / MPM（`pitchAlt.ts`）与 YIN 共享同一调度入口 `detectPitch(samples, sampleRate, minHz, maxHz, algo)`，
  `algo` 取自 `settings.pitchAlgorithm`（默认 `'yin'`）。**当前设置界面没有暴露这个开关**，
  因此正常使用恒为 YIN；导入的旧配置若指定了 pYIN / MPM 仍会生效。
  `pitchAlgorithm` 仍参与重算的参数指纹（`lib/audio/reanalyze.ts`）。

## 局限与改进方向

- 强噪声下仍可能出现倍频/半频跳跃，可用中值滤波后处理；
- 哑音段（气声、擦音）返回 null，曲线断开是预期行为；
- 更高稳健性的 pYIN 与更低成本的 MPM **均已实现**（`pitchAlt.ts`，见
  PARAMETERS-GUIDE.md「音高算法与对比卡」），可在分析页的对比卡里整段对比
  （把存档音频重算成 pYIN / MPM 曲线，与记录里保存的曲线叠放；该曲线默认由
  YIN 生成，导入配置指定 pYIN / MPM 录制时则是相应算法）；
- 若未来支持歌唱微调显示，可将置信度 prob 一并存储用于曲线透明度编码。

## 基准（本地合成语料）

`src/lib/audio/pitchBenchmark.test.ts` 以 golden fixture 同款的源滤波合成语料
（谐波声门源 + Klatt 共振器级联，C3–C5 × 干净/10dB 噪声 × 微颤）对三算法测
raw pitch accuracy（RPA，误差 ≤ 50 cents 的帧占比）与中位绝对误差。
本地运行 `npx vitest run src/lib/audio/pitchBenchmark.test.ts` 复现。

最近一次结果（32 kHz、2048 点窗、30 fps 帧步进）：

| 语料 | YIN | pYIN | MPM |
| --- | --- | --- | --- |
| 干净（C3–A4） | RPA 100%，中位 ≈ 4.5¢ | RPA 100%，中位 ≈ 4.5¢ | RPA 100%，中位 ≈ 4.0¢ |
| 10 dB 噪声 | **中位仍 < 13¢，但低频段出现半频跳跃（G3/A4 处 RPA 骤降）** | **全部判为无声（RPA 0）**——噪声把 CMND 谷推过其 12 档阈值范围，保守退出而非错报 | **RPA 100%，中位 < 13¢——对加噪元音最稳健** |
| C5 微颤 2% | RPA 100%，中位 17.6¢ | RPA 100%，中位 34.7¢ | RPA 100%，中位 16.3¢ |

结论与取舍：

- **干净语料三算法等价**（亚 5¢），选型只在噪声下有意义；
- **MPM 对加噪元音最稳健**，但实现更依赖峰值选取启发式，在极端语料
  （如脉冲串 + 强噪声）上需另行验证；
- **pYIN 在本实现的阈值分布下过于保守**：强噪声下整体退出（宁可 null
  也不错报倍频）。这符合「少倍频错误」的设计初衷，但「无声帧偏多」是
  代价——实时对比视图中 pYIN 曲线的断点会比另两者多，属预期行为；
- 测试内含干净语料 RPA ≥ 95% 的回归底线，防止算法改动引入退化。
